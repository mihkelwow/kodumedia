# KoduMedia 0.8.57

KoduMedia 0.8.57 is a critical browser-playback hotfix. It fixes the startup
buffer deadlock introduced in 0.8.56 and restores reliable HLS playback in
Windows Chromium browsers while retaining the AirPlay and Samsung DLNA work.

## Fixed

- Movies and episodes no longer remain indefinitely on the initial buffering
  screen when an HLS transcode reaches roughly ten seconds but the quality plan
  requests a 14–20 second encoder buffer.
- Browser playback now starts with a bounded buffer target and may proceed
  after six seconds when the media element confirms that playable data exists.
- Rebuffer recovery also uses a bounded browser target instead of waiting
  forever for a larger server-side quality target.
- Samsung and other DLNA playback keeps its independent 12–20 second
  server-side ready buffer. The AirPlay and MPEG-TS DLNA fixes from 0.8.56 are
  unchanged.
- Windows Chromium browsers use the proven hls.js playback path again, even if
  the browser advertises partial native HLS support. Native HLS is reserved for
  WebKit clients exposing the AirPlay playback-target picker, preventing the
  repeated `MediaError 4` failure on both normal and universal fallback streams.
- Generic media-element errors no longer race hls.js error recovery and create
  duplicate fallback sessions.
- Windows release archives now use ZIP-standard forward-slash entry names. The
  previous Windows packaging API emitted backslash entry names that the 0.8.56
  updater correctly rejected as ambiguous before reading the manifest.
- Packaging now reopens and verifies the completed archive, so an updater-
  incompatible ZIP cannot pass a green release build.

## Verification

- Player buffering regression tests pass.
- All 105 frontend tests pass.
- Type checking and the production build pass with the pinned TypeScript 6.0.3
  compiler used by the Windows workflow.
- UI foundation checks now support a clean checkout before the embedded web
  bundle exists, then verify that bundle explicitly after it has been built.
- The production Vite bundle builds successfully.
- Playback was verified manually with the final Windows test package.

## Update an existing installation

1. Download the complete `kodumedia-0.8.57-windows-x64.zip` asset below. Do not
   extract or rename it.
2. Back up the existing `data` folder.
3. In KoduMedia, open **Settings → System status → KoduMedia update**.
4. Select the downloaded ZIP and confirm the update.
5. Wait for KoduMedia to restart, then refresh the browser if necessary.

The updater verifies the release manifest and file hashes, preserves the local
`data` folder and rolls back if the new server does not become healthy.

## New installation

1. Download `kodumedia-0.8.57-windows-x64.zip` from this release.
2. Extract the complete ZIP to a writable folder.
3. Run `start-kodumedia.cmd`.
4. Open `http://localhost:8096`.

## Release assets

- `kodumedia-0.8.57-windows-x64.zip` — complete Windows portable and update
  package. This is the file normal users should download.
- `kodumedia-0.8.57-windows-x64.zip.sha256` — SHA-256 checksum for the package.

GitHub may also display automatically generated “Source code” archives. Those
archives are for developers and cannot be installed through KoduMedia's updater.

KoduMedia is intended for trusted private networks. Do not expose port `8096`
directly to the public internet.
