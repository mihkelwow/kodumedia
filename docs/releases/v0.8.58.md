# KoduMedia 0.8.58

KoduMedia 0.8.58 is a playback-stability release for long-running and seeked
HLS sessions. It removes an overly conservative producer throttle, builds a
substantially larger safety buffer and reports the encoder's recent production
rate instead of a misleading lifetime average.

## Improved

- A normal 1080p transcode now builds a 24-second startup cushion, restores to
  36 seconds after a stall and targets 90 seconds of buffered media.
- High-complexity 4K/HDR sessions use 30-second startup, 45-second recovery and
  120-second desired buffer targets.
- Seeking outside the existing browser buffer creates a fresh HLS session and
  waits for the complete startup cushion before playback resumes. The previous
  eight-second server-ready cap no longer exposes a nearly empty stream.
- The ordinary 1080p producer limit has increased from 1.30× to 2.50×, with a
  longer initial burst. Recovery profiles also retain substantially more
  production headroom.
- Runtime diagnostics now calculate recent output-media time per wall-clock
  time. A fast initial burst can no longer keep the displayed encoder speed
  artificially high while current production slows down.
- Automatic quality fallback requires both a sustained low client buffer and a
  server-confirmed encoder-speed problem. Browser `waiting` or `stalled`
  events alone no longer cascade through lower quality profiles.
- Automatic hardware encoding now prefers a validated NVIDIA NVENC path for
  SDR as well as 4K/HDR, followed by Intel QSV, AMD AMF and software encoding.
- The README now documents practical minimum and recommended hardware,
  Direct Play/remux/transcode selection, source preservation, encoder priority
  and audio passthrough behavior.

## Source preservation and audio passthrough

KoduMedia still chooses the least destructive compatible path:

- Direct Play sends a compatible source file unchanged.
- Remuxing changes only the container while copying compatible video and audio
  bitstreams.
- Transcoding converts only an incompatible track where possible.
- Compatible selected audio is stream-copied during Direct Play, remuxing and
  video-only transcoding. Unsupported audio is converted to AAC 192 kbit/s,
  stereo, 48 kHz.

The **Original** profile means that the source is preserved whenever the
receiving client can actually play it. HDR-to-SDR tone mapping, subtitle
burn-in, unsupported codecs or client resolution/channel limits can still
require transcoding.

## Update an existing installation

1. Download `kodumedia-0.8.58-windows-x64.zip`. Do not extract or rename it.
2. Back up the existing `data` folder.
3. In KoduMedia, open **Settings → System status → KoduMedia update**.
4. Select the downloaded ZIP and confirm the update.
5. Wait for KoduMedia to restart, then refresh the browser if necessary.

The updater verifies the release manifest and every packaged file hash,
preserves the local `data` folder and rolls back if the new server does not
become healthy.

## New installation

1. Download `kodumedia-0.8.58-windows-x64.zip`.
2. Extract the complete ZIP to a writable local folder.
3. Run `start-kodumedia.cmd`.
4. Open `http://localhost:8096`.

## Release assets

- `kodumedia-0.8.58-windows-x64.zip` — complete portable Windows package and
  the only ZIP accepted by KoduMedia's built-in updater.
- `kodumedia-0.8.58-windows-x64.zip.sha256` — Windows package checksum.
- `kodumedia-0.8.58-source.zip` — reviewed source snapshot for this release;
  not accepted by the updater.
- `kodumedia-0.8.58-source.zip.sha256` — source snapshot checksum.

GitHub also generates “Source code” archives from the `v0.8.58` tag. Those are
developer downloads and cannot be installed through KoduMedia's updater.

KoduMedia is intended for trusted private networks. Do not expose port `8096`
directly to the public internet.
